# 홈페이지 리디자인 제안

작성일: 2026-09-09. 목업: 이 문서와 함께 공유된 "TradingAgents Korea 홈 리디자인" 아티팩트.

## 1. 진단: 지금 홈은 무엇을 팔고 있는가

현재 홈(`render_public_home_page`)은 "한국 주식 AI 관제 시스템"이라는 다크 아트보드형
히어로(캔버스 신호 애니메이션, 스캔라인, 라이브 테이프)로 시작해 6개 섹션이 이어집니다.
실측치는 다음과 같습니다.

| 항목 | 값 |
|---|---|
| HTML 크기 | 226 KB (CSS 156 KB, JS 51 KB 인라인) |
| 본문 단어 수 | 약 650 |
| 첫 화면의 실데이터 | 없음 (히어로는 장식 그래픽) |
| "최근 공개 분석" 섹션 | 비어 있음 ("발행된 공개 AI 분석 리포트가 존재하지 않습니다") |
| 백엔드가 이미 만드는 데이터 중 홈에 없는 것 | 일일 하네스 결정, 5·20일 사후 성과, 모의투자 계좌, 스크리너 |

문제를 한 문장으로 하면, **제품이 매일 만들어 내는 증거(선정 종목·근거·채점 결과)가 홈에
없고, 그 자리를 설명 문구와 장식이 채우고 있다**는 것입니다. "관제 시스템", "시그널
맵", "아트보드" 같은 시스템 관점 어휘도 첫 방문자에게는 낯섭니다.

## 2. 목표

1. 첫 화면에서 세 가지 질문에 숫자로 답한다: 오늘 무엇을 골랐나, 왜 골랐나, 과거 선택은 맞았나.
2. 백엔드 산출물을 그대로 노출한다. 홈은 새 데이터를 만들지 않고 `/api/harness/*`,
   `/api/harness/outcomes`, `/api/prices/latest`, `/api/screener`를 읽기만 한다.
3. 페이지 무게를 1/3로 줄인다(목표 70 KB 이하, 인라인 JS 10 KB 이하).
4. 공개 사이트의 경계를 카피로 지킨다: 실계좌 주문 없음, AI 의견은 연구 자료.

## 3. 시각 방향: "증권사 데일리 리포트 1면"

한국 투자자가 매일 아침 읽는 증권사 데일리·호가창의 문법을 빌립니다. 장식 대신 표와
숫자가 페이지를 이끌고, 상승은 빨강·하락은 파랑(국내 관례)을 그대로 씁니다.

- **색**: 기존 토큰을 유지합니다. 종이 `#fbfaf4`, 잉크 `#17201f`, 강조 청록 `#146b63`,
  보조 황동 `#a87d24`, 상승 `#b42318`, 하락 `#1d4ed8`. 다크 테마는 기존 `home-bg
  #10130f` + 셀라돈 `#8fd8bd`. 다크 히어로에 쓰이던 형광 라임 `#d7ff3f`는 뺍니다.
- **서체**: 제목 Noto Serif KR 700(리포트 헤드라인의 권위), 본문 IBM Plex Sans KR,
  숫자 IBM Plex Mono(tabular). 현재의 Geist 단일 스택은 한글 본문에서 개성이 없습니다.
- **레이아웃**: 마스트헤드 → 시장 테이프 → 검색+성과 요약 → 오늘의 하네스 원장(표) +
  검증 성과 사이드바 → 5단계 프로세스 → 종목 분석실 레일 → 회원 안내 → 운영 원칙.
  히어로는 내용물 높이만큼만 차지하고 `100vh`를 쓰지 않습니다.

## 4. 섹션 명세와 데이터 소스

| 섹션 | 내용 | 소스 | 갱신 |
|---|---|---|---|
| 시장 테이프 | 날짜·KOSPI·KOSDAQ·오늘 스크리닝 규모·다음 실행 시각 | `/api/prices/latest`(지수는 pykrx 인덱스 추가 필요), 최신 하네스 run | 5분 캐시 |
| 히어로 검색 | 종목명/코드 검색, 첫 방문자용 샘플 링크 | 기존 `/stocks/{code}` | – |
| 성과 요약 3타일 | 5일 승률, 20일 평균 알파, 모의투자 계좌 수익률 | `/api/harness/outcomes` summary, 최신 KIS run의 `cash_after`/equity | 1시간 캐시 |
| 오늘의 하네스 | 깔때기(유니버스→필터→상위→통과→주문) + 결정 원장 표(단계·요인·예측·토론 등급·근거) | `/api/harness/runs/latest` | run 저장 시 |
| 검증 성과 | 5·20일 승률/알파, 최근 30건 알파 막대, 모의투자 계좌 현황 | `/api/harness/outcomes`, KIS run | 1시간 |
| 다섯 단계 | 스크리닝→예측→토론→수량/한도→가상주문·채점 (실제 순서이므로 번호 사용) | 정적 | – |
| 종목 분석실 | 6종목 카드: 현재가·등락·렌즈 5개 막대 | `/api/prices/latest`, `strategy_lenses` | 5분 |
| 회원 안내 | 관심목록 분석 요청, 브로커 계정 미수집 명시 | 정적 | – |
| 운영 원칙 | 실계좌 주문 없음, 출처·시각 표기, 투자 조언 아님 | 정적 | – |

빈 상태 규칙: 하네스 run이 없으면 "다음 실행 07:50"과 스크리너 후보 5개를 대신 보여
주고, 사후 성과가 10건 미만이면 승률 대신 "확정 n건, 표본 부족"을 표시합니다.

## 5. 카피 원칙

- 시스템 이름이 아니라 사용자의 행동으로 씁니다. "관제 시스템" → "오늘 살 만한 종목과
  지난 선택의 성적표".
- 숫자에는 항상 분모를 붙입니다. "58%" 단독 금지, "58% (14/24)".
- 주문 관련 어휘는 공개 사이트에서 "가상 매수", "모의투자"로만 씁니다(Gate 7 스캔 대상).
- 이모지 마커, "AI가 찾아낸 맥락" 같은 추상 문구를 제거합니다.

## 6. 구현 계획

1. **P1 (1~2일)**: `tradingagents/site/home_page.py`를 새로 만들어 목업 구조를 서버
   렌더링으로 옮깁니다. 기존 `render_public_home_page`는 `?legacy=1`로 남겨 비교합니다.
   페이지 전용 CSS는 12 KB 이내의 별도 상수로 두고 `PAGE_CSS`(156 KB)를 홈에서
   로드하지 않습니다.
2. **P2 (1일)**: `/api/harness/runs/latest`와 `/api/harness/outcomes` 응답에 홈이 쓰는
   요약 필드(깔때기 수치, 승률 분모, 최근 30건 알파)를 추가합니다. 지수 시세는
   `kr_returns`의 인덱스 조회를 재사용해 `/api/prices/latest?indices=true`로 노출합니다.
3. **P3 (반나절)**: 브라우저 스크린샷(데스크톱·태블릿·모바일), 콘솔, 오버플로 점검,
   `pytest -q`, `/api/readiness` 확인 뒤 배포. 나머지 페이지(`/harness`, `/outcomes`,
   종목 페이지)의 마스트헤드와 서체를 같은 토큰으로 맞추는 작업은 후속으로 분리합니다.

## 7. 측정

- 첫 화면 이탈률과 검색 사용률(검색 폼 제출 / 홈 방문).
- `/harness`, `/outcomes` 클릭률: 홈에서 증거로 이어지는지가 핵심 지표입니다.
- LCP 2.5초 이하(현재 캔버스 애니메이션과 156 KB CSS가 주요 원인).

## 8. 위험과 대응

- **성과 숫자가 나쁘게 나올 때**: 감추지 않고 그대로 보여 주는 것이 이 제품의 차별점입니다.
  분모와 기간을 함께 표기하고, 표본이 적을 때는 승률 대신 건수를 씁니다.
- **모의투자 계좌 노출**: 잔고는 표시하되 계좌번호·주문번호는 공개하지 않습니다.
- **다크 테마**: 토큰만 바꾸는 구조라 두 테마 모두 검증 대상입니다. 형광 강조색을 뺀
  만큼 셀라돈 강조가 대비 기준(4.5:1)을 만족하는지 확인합니다.
